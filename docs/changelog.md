# Changelog

### v0.1.1
- `TestOverheadBudget` (PLT-18) вынесен в `internal/app/overhead_test.go` с ограничением сборки `//go:build !race`: под `-race` тест не собирается, без `-race` по-прежнему проверяет p95 не больше 15 мс; в лог выводятся объём выборки (`requests=200`) и бюджет (`budget_ms=15`). CI дополнительно гоняет `go test -race -p 1 ./...` (F-1).
- Пропуск пассивного запроса (`skipped`) решает только сессия: конвейер больше не ведёт свой учёт запросов, слот свободен с момента отмены или замены запроса, а пассивный запрос, получивший `accepted`, больше не получает `skipped`. Тест конвейера `TestPassive/must_pass_skipped` заменён тестами сессии `TestSession_PassiveSlots` (F-2).
- Закрытие сессии и остановка Шлюза ждут конвейеры, активные запросы и закрытые сессии по событию, без опроса и `time.Sleep`; сроки (`drainTimeout` 2 с, `DefaultShutdownGrace` 5 с) и предупреждения прежние (F-3).
- Тело ошибки поставщика языковой модели дочитывается до 128 КиБ с таймаутом простоя: соединение возвращается в пул и переиспользуется, зависшее тело не задерживает ответ (F-4).
- Снимок, пришедший для пропущенного пассивного запроса, убирает его id и из карты, и из очереди пропущенных; вытеснение старейшего срабатывает только по числу ещё ожидаемых id, повторный пропуск того же id очередь не дублирует (F-5).
- Устранена гонка остановки: запрос учитывается остановкой и сессией до того, как `accepted` ставится в очередь, поэтому остановка сразу после `accepted` всегда дожидается `answer.end` до закрытия 1001. Запрос, пришедший во время остановки, получает `error` с кодом `busy` без предшествующего `accepted`. Тест `TestSession_Cancel/must_pass_new_request_cancels_previous` ждёт то же значение `alv_requests_total`, которое растёт после последнего сообщения (Р-7).
- Тест `TestSentenceStreaming/must_pass_audio_in_order` детерминирован без задержки по времени: заглушка TTS (`servicestub.TTS.FinishAfter`) держит синтез первого предложения, пока синтез второго не отдаст последний фрагмент, а второй - пока не придёт первый. Так оба синтеза идут одновременно, а первый всегда заканчивается позже второго, как с задержкой 150 мс в `v0.1.0`. Заглушка записывает порядок окончаний синтезов (`Finished`), и тест проверяет, что этот сценарий случился; прежние утверждения и ожидаемые значения не менялись (Р-8).
